## 一、业务背景与系统定位




工商业分布式光伏，指建在工厂厂房屋顶、产业园区、商业综合体屋顶或场内空地上的光伏电站，区别于地面集中式电站和户用光伏，有几个业务特点必须先搞清楚，否则页面设计会失真：




1. **资产分散、单站规模小、站点数量多**。一个运营商/运维公司通常同时管理几十到上千个分布在不同城市屋顶的电站，因此系统天然需要"集团汇总 → 单站下钻"的两级（或多级）视角，而不是像地面电站那样单站深度运营。

2. **电价结算模式决定了收益计算逻辑**，常见三种，页面上的"收益"模块必须能区分：

   - **自发自用、余电上网**（工商业最主流）：企业自己消耗的电量按"目录电价 × 折扣"结算给业主，多余上网的电量按当地燃煤基准价/上网电价结算给电网公司。收益 = 自用电量 × 自用结算单价 + 上网电量 × 上网电价。

   - **全额上网**：全部发电量按标杆/上网电价卖给电网，收益 = 总发电量 × 上网单价。

   - **分布式交易/隔墙售电**：光伏业主与周边企业直接签订购售电协议，价格由合同约定，可能是分时电价。

   - 因此电价模型页面需要支持"自用比例、余电上网比例、分时电价（尖/峰/平/谷）、合同单价"这几个可配置项，而不是写死一个电价。

3. **屋顶资源归属复杂**：屋顶业主（厂房所有者）、光伏投资方（EPC/运营商）、用电企业三方角色常常不是同一家，因此系统需要"电站基本信息"里包含合同信息（租赁期限、收益分成比例、并网日期）。

4. **组件遮挡、积灰、局部热斑是工商业屋顶电站的高发问题**（相比地面电站更容易被水箱、女儿墙、临近建筑遮挡），因此"组串级电流对比"和"PR 性能比分析"是差异化的核心监控功能，不能只做到逆变器级别。

5. **通信链路薄弱**：多站分散、4G/NB-IoT 采集为主，断线率高，"设备/网关在线率"和"通信告警"是系统里权重很高的一类功能，不能被简化掉。

6. **储能（BESS）正在快速成为标配**（削峰填谷、需量管理、避免逆流限电），本设计按用户要求预留"光储一体"监控入口，但不展开储能内部详细设计。




### 关键角色与对应视角




| 角色 | 关注点 | 对应端 |

|---|---|---|

| 集团/运营商管理层 | 全局装机、总发电量、总收益、告警总览、电站分布地图、在线率 | 集团监控大屏 |

| 运维工程师/巡检人员 | 单站设备台账、逆变器/组串异常、告警工单、巡检计划、备件 | 运维管理后台 |

## 二、监控对象与资产层级模型




这是整个系统的数据骨架，页面导航、图表下钻、告警归属都基于这套层级：




```

集团 / 运营商

 └─ 区域（省/市，用于地图聚合）

     └─ 电站 Station（一个屋顶或一个项目，含并网点）

         ├─ 光伏方阵/子阵 Array（同一朝向/倾角的一组组件，可选层级，小站可省略）

         │   └─ 逆变器 Inverter（组串式为主，集中式配汇流箱）

         │       ├─ 汇流箱 Combiner Box（仅集中式逆变器项目存在）

         │       │   └─ 组串 String（若干块组件串联）

         │       └─ 组串 String（组串式逆变器直接挂在逆变器下，无汇流箱）

         ├─ 计量点 Meter Point

         │   ├─ 关口表 / 上网表（与电网结算用，法定计量）

         │   ├─ 用户侧用电表（企业总用电）

         │   └─ 光伏发电表（逆变器侧或并网点侧）

         ├─ 箱变/站用变 Transformer（升压、站用电）

         ├─ 气象站 Weather Station（辐照度、组件温度、环境温度、风速风向）

         ├─ 储能子系统 BESS（预留入口：PCS、电池簇、SOC/SOH，不展开）

         ├─ 采集网关 Data Logger / Gateway（每个站至少一个，决定通信在线率）

         └─ 安防设备（可选：摄像头、烟感、门禁，工商业屋顶电站常见消防合规要求）

```




**必须体现在设计中的层级关系逻辑：**

- 装机容量（组件标称功率之和，DC 侧）与并网容量（电网核准的 AC 侧容量，通常受限）不是一个数，超配比（DC/AC ratio）在工商业项目里常见 1.1~1.3，页面要能分别展示。

- 组串电流对比只在"同一逆变器下的多路组串"之间做横向对比才有意义（不同逆变器/不同朝向不能直接比较）。

- 告警必须挂在具体设备节点上并能沿层级向上汇总（例如某组串异常 → 影响该逆变器发电效率 → 影响电站 PR）。

## 三、核心业务计算逻辑（页面上的数字必须遵守这些口径）




1. **实时功率**：各逆变器 AC 侧实时功率求和，采集频率建议 1~5 分钟。

2. **发电量统计**：日/月/年/累计发电量，来自逆变器电表或计量表的电量累计值差分，需支持同比（去年同期）、环比（上一周期）、与预测值/目标值对比三种对比方式。

3. **等效利用小时数** = 统计周期发电量 ÷ 装机容量（单位 kWh/kWp = h），用于跨电站可比性分析（不同容量电站发电量没法直接比，等效小时数可以）。

4. **PR 性能比（Performance Ratio）** = 实际发电量 ÷ 理论发电量；理论发电量 = 装机容量 × 有效辐照量(peak sun hours) × 系统设计系数。PR 是判断电站健康度最核心的单一指标，行业健康值一般在 80%~85% 以上，低于该值需要触发分析（组件衰减/污损/遮挡/逆变器限功率/线损）。

5. **组串异常诊断规则**：取同一逆变器下所有在线组串电流的中位数或均值为基准，单路电流持续低于基准的一定比例（例如 <70%~80%，具体阈值应做成可配置项，而不是写死）超过设定时长，判定为"组串异常"，需要在 UI 上高亮并归类为遮挡/污损/线路/组件故障待人工确认。

6. **收益计算**：按第一部分的三种电价模式分别计算，页面需要能配置电价参数（自用电价、上网电价、分时尖峰平谷、合同折扣率）而不是硬编码单一电价。

7. **CO2 减排/等效植树**：发电量 × 电网排放因子（页面可配置默认系数，不同地区电网排放因子不同，需注明"系数可配置/据当地电网基准线"，不要给出一个放之四海皆准的假数字当真理）。

8. **设备/网关在线率** = 周期内正常上报数据的时长 ÷ 总时长，通信中断超过设定分钟数即触发"通信告警"，这是工商业分布式电站里最高频的告警类型之一。

9. **告警分级建议**（供页面告警列表筛选/统计用）：

   - 紧急（红）：逆变器故障停机、电网侧保护动作、消防/安全类告警

   - 重要（橙）：PR 持续低于阈值、组串异常、限功率

   - 一般（黄）：通信中断、气象站数据异常

   - 提示（蓝）：计划性维护/清洗提醒、软件版本/证书到期




以上逻辑将写入下面的提示词中，要求 Lovable 生成的 mock 数据和图表口径与之一致，避免生成"看起来好看但业务上说不通"的界面。

## 四、三端功能架构（用户已确认三种视角都要）




### A. 集团监控大屏（深色科技风，运营商管理层用）

- 顶部 KPI 条：总装机容量、今日发电量、当前实时总功率、累计发电量、今日/累计收益、今日/累计 CO2 减排、电站总数与在线率

- 中国地图/区域地图：电站气泡分布，气泡大小=装机容量，颜色=运行状态（正常/告警/离线）

- 实时功率趋势曲线（全网汇总，24h）

- 发电量排行榜（电站 Top N，按日/月发电量或按 PR 排序，用于发现异常站）

- 告警总览：分级数量统计 + 最新告警滚动列表

- 设备在线率环形图（逆变器/网关/气象站分别统计）

- 天气与辐照度概览（选中区域/电站的当日辐照曲线）

- 光储一体入口（预留卡片：接入储能站点数、当前充放电功率占位，暂不展开详情）




### B. 运维管理后台（浅色专业后台，运维工程师/管理员用）

- 电站列表（表格+筛选：区域/状态/装机容量/建成时间/PR），点击进入电站详情

- 电站详情页（这是系统里信息密度最高的页面）：

  - 概览卡片：实时功率、今日/月/年发电量、PR、等效小时数、并网信息、超配比

  - 设备台账 Tab：逆变器列表（状态/效率/温度/故障码）、汇流箱列表、组串电流对比图（同逆变器下多路对比，异常高亮）

  - 气象 Tab：辐照度/组件温度/环境温度/风速曲线，叠加理论发电量对比实际发电量

  - 收益 Tab：电价模式配置、自用/上网电量拆分、日/月/年收益趋势

  - 告警 Tab：该电站历史与当前告警列表，支持转工单

  - 设备档案/点位配置 Tab（系统管理员用）

- 逆变器详情页：MPPT 路数电压电流表格、直流/交流参数、日发电曲线、故障代码历史

- 告警中心（全局）：跨电站告警列表，筛选（电站/等级/类型/状态/时间），支持派单、处理、关闭、时间线记录

- 工单管理：工单列表（新建/处理中/已完成）、关联告警、关联电站与设备、处理人、处理记录

- 巡检与维护：巡检计划日历、组件清洗计划、备件库存（简单列表即可）

- 报表中心：日/月/年报表生成、发电量对比分析、PR 分析报告、导出（PDF/Excel，前端可只做导出按钮占位）

- 组织与权限：组织架构树（集团/区域/运维公司）、账号列表、角色权限矩阵、电站授权分配

- 光储一体子模块（预留）：储能站点列表占位、PCS 状态占位、SOC 曲线占位，明确标注"储能详情待扩展"




### C. 业主/投资方收益门户（浅色，简洁财务视角，可与运维后台共享布局但菜单精简）

- 我的电站列表（卡片视图：电站名、装机容量、今日发电、累计收益）

- 电站收益详情：发电量趋势、收益趋势、结算电量对比（关口表 vs 逆变器侧，用于核对线损/自用比例）

- 合同信息卡片：屋顶租赁方/收益分成比例/合同起止日期/并网日期

- 报表下载（月度结算单、年度发电报告）

## 六、使用建议




1. 建议先把上面代码块整体丢给 Lovable 生成初版骨架，Lovable 一次性吃太多细节可能会裁剪，如果生成结果页面数量不够，可以分批次追加提示词（例如先出"大屏+电站列表+电站详情"，再补"告警中心+工单+报表"）。

2. mock 数据口径（PR、超配比、电价模式）建议在后续找懂业务的同事再核对一遍具体数值区间，本文档给出的是行业通用经验值，不同地区、不同电网公司政策会有差异。

3. 如果后续要接入 MyEMS 真实后端，Inverter/StringPV/WeatherRecord/MeterReading 这几个模型建议直接对齐 MyEMS 的 point/data 采集点表结构，会省掉很多字段映射工作。
